Exercise library — v1 prototypes

Three ways to lay out the same library with add, edit, tag, duplicate, archive and delete. All three use the shipped Primer stylesheet and the same mock data, and every control works in memory. Reload a page to reset it.

Problems in the current page

  • All 767 rows render at once in per-muscle panels, so the page is about 47,000px tall and finding one exercise means scrolling.
  • The Pattern select is too narrow to read ("h p…"), and raw keys like full_body appear in the UI.
  • WGER entries and the trainer's own exercises look the same. There is no add, edit or delete, so the trainer can't fix a wrong muscle or remove a duplicate.
  • "300 untagged" is the biggest job on the page but only appears as a line of text. Untagged exercises are invisible to balance checks.
  • The subtitle reads like a developer note ("the real seed holds 719 from WGER").
  • WGER contains non-English duplicates ("Croci su panca piana", "Klimmzüge an der Stange"). Each direction can hide them, and the seed could be filtered.

Rules shared by all three directions

WGER entriesLocked: the trainer can tag the pattern and functional movement and add a coaching note. To change the name, muscles or equipment, they duplicate it into their own exercises. "Delete" becomes Hide from library.
Your exercisesFully editable. Marked with a blue "Mine" label.
DeleteOnly for custom exercises not used in any program. If a program uses it, the action becomes Archive: hidden from pickers and the AI, while existing programs and logs keep it. Every removal shows a flash with Undo.
CreateRequires name, primary muscle and equipment. As the trainer types a name, the form lists similar exercises already in the library ("Already in the library: Pendlay Row"). An exact name match is blocked.
Coaching noteA new field: setup cues stored per exercise, shown in programs and passed to the AI. It needs a DB column.

Directions

A · Sheet & inspector

One paged, filterable table with an edit panel on the right. It works like an issue list and is built for scale and bulk work.

Find
Tabs (All / Mine / Needs tagging / Archived), search with /, filter menus for muscle, pattern and equipment, and sorting
Edit
Click a row and the inspector opens beside the list. Save is enabled only after a change.
Bulk
Select rows to set a pattern or functional tag, or to archive, in one step
Best if
The trainer will tag hundreds of WGER entries
Open prototype →

B · Groups & inline edit

Keeps today's grouped view but adds a group index on the left and lets the trainer edit a row in place.

Find
Group by muscle, pattern or equipment, with an amber dot on groups that have exercises to tag
Edit
Pattern and functional selects sit right in each row. The edit icon expands the row into a full form. ⌘↵ saves.
Add
"Add a back exercise" at the bottom of each group prefills the muscle
Best if
The trainer thinks in body parts and edits occasionally
Open prototype →

C · Coverage map

A pattern × equipment grid in the contributions-green ramp sits above the list. Empty cells show exactly which options are missing.

Find
Click a cell, a row or a column to list those exercises
Edit
A drawer slides in over the page. Delete takes two steps (the second turns red).
Add
"Add one" on an empty cell opens the form with that pattern and equipment filled in
Best if
The goal is a balanced library the AI can draw from
Open prototype →

My recommendation: A as the page, with C's map as a collapsible panel above the table, where clicking a cell sets the filters. A handles 767 rows and bulk tagging. The map is the one view no spreadsheet gives the trainer.
